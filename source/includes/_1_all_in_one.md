# Метод получения структуры XML отгрузки через API

Этот эндпоинт предназначен для интеграций и решений, которым необходимо получать структуру XML-файла УПД или ЭТрН, сформированную на основе документа «Отгрузка» в МойСклад.

XML формируется по тем же правилам, что и при экспорте документа через пользовательский интерфейс:

* УПД: Отгрузка → ЭДО → экспорт XML УПД;
* ЭТрН: Отгрузка → ЭДО → Экспортировать XML ЭТрН.

Версия документации 2

## URL и метод

```
GET https://online.moysklad.ru/api/gov_fns/demand/{uuid}
```

Где `{uuid}` — идентификатор отгрузки в формате `8-4-4-4-12` шестнадцатеричных символов.  
Некорректный формат приводит к ошибкам.

Тело запроса не используется и игнорируется.

## Авторизация

Эндпоинт поддерживает два метода:

### Basic

```
Authorization: Basic <Base64(username:password)>
```

### Bearer

```
Authorization: Bearer <token>
```

где `<token>` — токен, который можно получить:

- на UI МоегоСклада в реестре [Токены](https://online.moysklad.ru/app/#token);
- с помощью [JSON API](https://dev.moysklad.ru/doc/api/remap/1.2/);
- с помощью [Vendor API](https://dev.moysklad.ru/doc/api/vendor/1.0/) для работы решения.

## Заголовки запроса

```
Authorization: <один из методов авторизации>
Accept-Encoding: gzip
```

## Параметры URL

Параметры опциональны. Их назначение — выбрать тип и версию XML-документа и обеспечить обратную совместимость при появлении новых версий.

### decree_type

Префикс типа документа.

| Допустимое значение decree_type | Документ | Примечание |
|---|---|---|
| ON_NSCHFDOPPR | УПД | Значение по умолчанию, если параметр decree_type не передан |
| ON_TRNACLGROT | ЭТрН | |

### decree_version

Версия схемы XML. Допустимое значение зависит от decree_type.

| decree_type | Допустимое значение decree_version | Примечание |
|---|---|---|
| ON_NSCHFDOPPR | 5.03 | Значение по умолчанию, если параметр decree_version не передан |
| ON_TRNACLGROT | 5.01 | |

### Использование параметров URL

| decree_type | decree_version | Результат |
|---|---|---|
| не передан / ON_NSCHFDOPPR | не передан / `5.03` | XML УПД 5.03 |
| ON_TRNACLGROT | `5.01` | XML ЭТрН 5.01 |

Иное значение или несовместимая пара параметров → `400 Invalid Parameter` (code `1014`).

Неизвестные параметры игнорируются.

## Успешный ответ

```
HTTP 200 OK
Content-Type: text/xml; charset=windows-1251
Content-Encoding: gzip
```

Тело ответа содержит **структуру XML-файла**, сформированную на основании указанной отгрузки.  
Это **не скачиваемый файл**, а XML-документ в теле ответа.

Тип XML определяется параметрами запроса (УПД или ЭТрН).

## Ошибки

Формат тела определяется заголовком:

```
Content-Type: application/json
```

Тело содержит массив `errors` с полями `error` и `code`.

### Основные случаи ошибок

| HTTP | code | Описание |
|---|---|---|
| 401 | 1056 | Ошибка аутентификации |
| 403 | 1064 | Недостаточно прав на печать отгрузки |
| 400 | 1014 | Некорректное значение параметра или несовместимая пара `decree_type` / `decree_version` |
| 412 | 1000 | UUID в неверном формате |
| 404 | 1002 | Отгрузка не найдена |
| 405 | 1039 | Метод не поддерживается |
| 5xx | 1999 | Ошибка формирования XML |

Пример:

```json
{
  "errors": [
    {
      "error": "Неверное значение '5.01' параметра фильтрации 'decree_version'",
      "code": 1014
    }
  ]
}
```

## Особенности формирования XML структуры

### ON_NSCHFDOPPR (УПД)

Структура XML формируется приближенной к требованиям приказа ФНС России от 19.12.2023 N ЕД-7-26/970@ для файла обмена счёта-фактуры в ред. Приказа ФНС РФ от 15.11.2024 N ЕД-7-26/1032@ (соответствует версии схемы 5.03).

Для загрузки структуры XML в другие информационные системы может быть необходимо привести её в полное соответствие требованиям законодательства. Обратите внимание на следующие особенности.

#### Идентификаторы отправителя и получателя

Указанное значение в структуре XML в атрибуте `ИдФайл` элемента `Файл` не содержит идентификаторов участников электронного документооборота

```
Значение в ответе:
ИдФайл="ON_NSCHFDOPPR___20251127_6df2ba12-aa0b-499a-8031-020340dad7d7_0_1_0_0_0_00"

Требуемые изменения:
ИдФайл="ON_NSCHFDOPPR_|идентификатор получателя|_|идентификатор отправителя|_20251127_6df2ba12-aa0b-499a-8031-020340dad7d7_0_1_0_0_0_00"
```

Узнать идентификатор участника электронного документооборота можно с помощью инструментов вашей системы электронного документооборота

#### Элемент "Подписант"

Структура XML, получаемая в ответе, всегда содержит обязательный элемент `Подписант` — его содержимое заполняется из данных пользователя в аккаунте МоегоСклада. В случае, если для выполнения запроса используется схема авторизации `Bearer <token>`, где токен был получен через [Vendor API](https://dev.moysklad.ru/doc/api/vendor/1.0/) — значения в элементе `Подписант` будут выгружены как пустые строки:

```
Значение в ответе:
<Подписант СпосПодтПолном="">
    <ФИО Фамилия="" Имя=""/>
</Подписант>

Требуемые изменения
<Подписант СпосПодтПолном="6">
    <ФИО Фамилия="Иванов" Имя="Иван"/>
</Подписант>

* значение атрибута СпосПодтПолном следует выбирать в соответствии с требованиями законодательства
```

### ON_TRNACLGROT (ЭТрН)

Структура XML формируется по тем же правилам, что и экспорт XML ЭТрН из пользовательского интерфейса Отгрузки. Версия схемы — `5.01` (`ВерсФорм="5.01"`).

Для загрузки структуры XML в другие информационные системы может быть необходимо привести её в полное соответствие требованиям законодательства и оператора ЭДО. Обратите внимание на следующие особенности.

#### Идентификаторы отправителя и получателя

Указанное значение в структуре XML в атрибуте `ИдФайл` элемента `Файл` не содержит идентификаторов перевозчика-получателя, грузополучателя и грузоотправителя.

```
Значение в ответе:
ИдФайл="ON_TRNACLGROT____0_20220315_9df1e567-6efd-4d61-be7d-238d0a5e18c1"

Требуемые изменения:
ИдФайл="ON_TRNACLGROT_|идентификатор перевозчика-получателя|_|идентификатор грузополучателя|_|идентификатор грузоотправителя|_0_20220315_9df1e567-6efd-4d61-be7d-238d0a5e18c1"
```

#### Элемент "Подписант"

Правило заполнения элемента `Подписант` такое же, как для УПД: при авторизации через `Bearer <token>`, полученный через [Vendor API](https://dev.moysklad.ru/doc/api/vendor/1.0/), значения в элементе `Подписант` выгружаются как пустые строки.
